# Проверка выпуска Windows 0.7.1

Статус текущей облачной среды: Linux. Здесь проверяются Go/PostgreSQL, интерфейс в Chromium и кросс-сборка EXE. Нативный Windows-прогон **не подтверждён**. Доступ к результатам GitHub Actions через API в этой среде возвращает Forbidden; успешный push сам по себе не доказывает прохождение Windows job.

## Подготовленная автоматизация

[checks.yml](../.github/workflows/checks.yml), job windows:

- Проверки Go/TypeScript, сборка Wails.
- Нативный тест Windows Credential Manager: запись/чтение случайного синтетического секрета под отдельным именем сервиса и удаление после теста. Прикладные реквизиты не используются.
- Загрузка официального WebView2 bootstrapper и проверка подписи Microsoft.
- Сборка Inno Setup для прошлого EXE 0.7.0 и текущего 0.7.1 с одинаковым AppId.
- [windows-smoke.ps1](../packaging/windows-smoke.ps1): установка 0.7.0 в случайный временный каталог, синтетический connection.json в отдельном LOCALAPPDATA, обновление на 0.7.1, сверка хеша EXE и сохранности файла настроек, создание нативного окна с --setup-connection, удаление тестовой установки.
- Логи установщика и results.json — артефакт CatalogDB-windows-smoke-report; EXE/установщик — CatalogDB-windows-x64.

Smoke-сценарий запускается **только в чистой Windows VM** и отказывается работать при уже зарегистрированном CatalogDB, чтобы не менять настоящую установку. Создание окна не доказывает визуальную корректность WebView2 или работоспособность диалогов.

Запуск вручную из PowerShell 7 после сборки обоих установщиков:

~~~powershell
go test -run TestNativeWindowsCredentialManager -v .
./packaging/windows-smoke.ps1 -OldInstaller build/bin/CatalogDB_Setup_0.7.0.exe -NewInstaller build/bin/CatalogDB_Setup_0.7.1.exe -ExpectedExe build/bin/CatalogDB.exe
~~~

## Интерактивный прогон перед выпуском

Запишите версию Windows, WebView2, EXE SHA-256 и фактические результаты:

| Область | Что проверить |
| --- | --- |
| Установщик | Чистая Windows 10/11 x64; стандартный/заданный путь; ярлык; первый запуск; установка WebView2 на машине без Runtime |
| Обновление | Настоящий запуск 0.7.0 → 0.7.1; сохранение подключения, загрузок и системного пароля; закрытие работающего приложения при обновлении |
| База | Отдельная тестовая PostgreSQL 17; актуальная схема 008 без DDL при обновлении с 0.7.0; существующие данные/права; новая схема |
| Credential Manager | «Запомнить пароль», перезапуск и автоподключение; --setup-connection; разные схемы и отсутствие сохранённого секрета |
| RDP | Наличие mstsc; доступный тестовый сервер; видимое окно; сертификат/авторизация; недоступный порт/адрес |
| SSH | Установленный OpenSSH Client, окно терминала, интерактивная авторизация, выход; машина без клиента, недоступный порт |
| Диалоги и загрузки | Сохранить XLSX/отменить/нет прав; открыть в ассоциированном приложении; показать в Explorer; отсутствующий/повреждённый файл |
| Интерфейс | Масштаб 100/125/150%; прокрутка; окна и Esc/Tab; массовый предпросмотр; восстановление; исправления политик РК |

Для RDP/SSH нужны разрешённые тестовые узлы и интерактивная сессия. Наличие клиента или открытого TCP-порта не подтверждает успешное удалённое подключение. Не отмечайте эти проверки как пройденные по одному запуску Linux-тестов или сборке.
