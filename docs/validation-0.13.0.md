## Нативный Android

APK установлен на программный планшетный эмулятор 1280×800, Android 15 / x86_64, без KVM. Первый AOSP-образ r2 с WebView 124 аварийно завершал renderer. Такое же падение воспроизведено минимальным отдельным WebView-приложением без Go/CatalogDB. Это ограничение тестового образа; его успешной проверкой приложения считать нельзя.

На GitHub Actions выполнен настоящий нативный прогон с KVM: Android 15 / Google APIs / x86_64, профиль Nexus 7. [Проверенный workflow](https://github.com/yomezza/dbcatalog/actions/runs/40208820170), исходники `dfac0cb`. Все четыре задачи — backend, Windows, Linux, Android — завершились успешно.

Две фазы instrumentation проверили:

1. Загрузку настоящего WebView и JS → Java → Go bridge; диагностика вернула `android/amd64` и Android Keystore.
2. Подключение к отдельной PostgreSQL 17 в CI, автоматические миграции новой синтетической схемы, создание администратора и сохранённый вход на 24 часа.
3. Запись сервера в PostgreSQL и получение настоящего события LISTEN/NOTIFY обратно в JavaScript.
4. Формирование XLSX и локальную историю загрузок.
5. Остановку процесса, чтение сохранённого пароля из Keystore, повторное подключение и восстановление токена сеанса; созданная запись сохранилась.

Instrumentation APK расположен отдельно в `android/tests` и не входит в пользовательский APK. CI использовал одноразовый тестовый сертификат, release APK подписан отдельным постоянным ключом; код и набор ABI совпадают. Полные логи двух фаз доступны в артефакте `CatalogDB-android-native-report` указанного workflow.

Программный локальный Google APIs эмулятор без KVM загружался около 17 минут; его нестабильность не используется как положительный результат теста. Для воспроизведения рекомендуются аппаратное ускорение/KVM или физический планшет.

## Пределы проверки

Браузерные тесты имитируют native transport и не проверяют Keystore или Android picker. Go integration использует настоящий PostgreSQL, но запускается на Linux. Сборка и подпись APK подтверждают упаковку и архитектуры, а не всю работу на планшете.

Физический Android-планшет, корпоративный VPN/TLS, сторонние обработчики документов и RDP/SSH здесь не проверены. Работа без актуального системного WebView не гарантируется. Постоянной фоновой службы и системных push-уведомлений нет; после возврата приложение повторно читает данные.

Windows CI подтвердил автоматическую установку/обновление и появление нативного окна; отдельный интерактивный прогон отображения, диалогов и RDP/SSH на рабочей Windows не выполнялся. Linux-архив этой среды требует glibc 2.41+, GTK 3 и WebKitGTK 4.1.

Закрытый Android signing key и пароли находятся вне Git. Для будущего обновления APK нужен тот же ключ; CI использует отдельный одноразовый тестовый сертификат. См. [Android: установка, сборка и подпись](android.md).
