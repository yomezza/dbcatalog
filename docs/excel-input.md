# Формат Excel и результаты проверки

Получен исходный XLS. В книге два листа: «Новая версия» — согласованный формат на 28 колонок; «Старая версия» — иной формат на 12 колонок и автоматически не импортируется. Также поддерживается XLSX с теми же заголовками. Разрывы строк в заголовках нормализуются.

Первые 21 колонки основного каталога:

1. SID — база данных (одна строка на БД).
2. Экземпляр.
3. Состояние.
4. Тип эксплуатации.
5. Имя сервера.
6. Тип СУБД.
7. Версия СУБД.
8. Подключение к серверу.
9. Доменное членство.
10. IPv4-адрес.
11. Месторасположение.
12. Информационная система.
13. Обслуживающая организация.
14. Сопровождение (руководитель).
15. Ответственное лицо.
16. Операционная система.
17. Версия системы.
18. Семейство системы.
19. Назначение.
20. Работа АБД — несколько значений; разделители `;`, перевод строки, `|` или запятая.
21. Персональные данные.

Дополнительные 7 колонок: Тип РК; Путь РК; Служба планировщика заданий; Статус СРК; Срок хранения РК; Пароль от архива; Прошлый пароль от архива.

В предоставленном листе 64844 строки с учётом шапки. 64235 строк содержат только шаблонные значения `default` и месторасположение по умолчанию. После их исключения — 608 кандидатов, из них 607 содержат SID/имя сервера/IP; одна строка содержит только состояние и тип эксплуатации без идентификации. Такие неполные строки не теряются молча, а показываются в отчёте ошибок. Строгая проверка повторяющихся параметров и справочников выявляет дополнительные конфликты — их исправляют в источнике либо явно пропускают в предпросмотре.

Исходный файл и его реальные записи не включены в репозиторий. Для локальной интеграционной проверки можно задать `CATALOGDB_XLS_SAMPLE` путём к частному файлу; проверка читает только предпросмотр и не записывает исходные записи в каталог.

Начиная с 0.5.0, для Oracle Database колонка «Экземпляр» игнорируется, включая пустое значение и `default`. SID размещается непосредственно под сервером и сопоставляется по серверу + точному SID. В экспорте экземпляр для Oracle пустой, тип и версия Oracle берутся из карточки БД. Для остальных СУБД экземпляр обязателен. Одинаковые SID на разных серверах/в разных обычных экземплярах допустимы; глобальной уникальности SID нет. Конфликты общих параметров сервера показывают номера строк и различающиеся поля (IP, ОС, подключение, домен, месторасположение, версия/семейство ОС). Сервер сопоставляется по имени без учёта регистра и крайних пробелов; разные имена из-за одинакового SID не объединяются.

### Политики и секреты

В файле нет расписания резервного копирования. Единицы срока хранения и трактовка некоторых значений требуют подтверждения; уровень политики необходимо подтверждать по реальному экземпляру, а не только серверу. До реализации этого этапа импорт 28 колонок требует явного подтверждения переноса только каталога; ручные политики доступны в приложении.

Две колонки паролей не переносятся в объектную модель импорта, PostgreSQL, журналы или историю. Предпросмотр показывает только число строк, в которых такие поля заполнены. Для будущего переноса секретов потребуется согласованное защищённое хранилище; обычные текстовые поля не используются.


В 0.6.0 любую строку предпросмотра можно исключить из плана, в том числе неполную строку со случайно заполненным состоянием. Есть массовое исключение всех текущих ошибок и возврат исключённых строк. Исходный файл не меняется, номера строк сохраняются. После каждого изменения состава заново проверяются дубли и общие параметры оставшихся строк, прежнее подтверждение недействительно. Исключённые строки не попадают ни в каталог, ни в исправленную копию XLSX; отдельно учитываются в итоговом отчёте. Автоматически проигнорированные пустые строки шаблона и вручную исключённые строки считаются отдельно.
