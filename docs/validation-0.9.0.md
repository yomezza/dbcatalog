# Проверки 0.9.0

В облачной Linux-среде с PostgreSQL 17.11:

- Финальный полный Go-прогон: 75 тестов прошли с race detector; 2 необязательных теста частного XLS пропущены.
- go vet — без замечаний.
- Vitest: 14 тестов прошли.
- Playwright/Chromium: 41 сценарий прошёл; после последней правки защиты от ответов старой сессии и backoff повторно прошли 5 затронутых сценариев.
- TypeScript strict/noUnused и production Vite build прошли в составе Wails-сборки.
- Windows amd64 EXE собран; Windows native test EXE скомпилирован.
- ZIP проверен на повреждения и соответствие EXE; SHA-256 и git diff --check проверены.
- Контрольные суммы миграций 001–009 не изменены. .gitattributes закрепляет LF для SQL, чтобы Windows checkout не менял встроенные контрольные суммы; экспорт bundle также пишет LF.

Интеграционные тесты создают случайные схемы с синтетическими данными и удаляют их. Рабочая БД пользователя не использовалась.

## Миграции

Проверен переход именно с 009: обычные и Oracle БД, политика экземпляра, вложение, избранное, два состояния истории с отличающимся legacy-полем, версии и аудит за три года.

Сравнены полные JSON-наборы аудита, истории и версий до/после. Проверены перенос байтов вложения, поисковый backfill, секции, сохранение ID/последовательностей, прямой UPDATE с новой версией, обработка будущей даты через DEFAULT и перенос в новую секцию, повторное обслуживание/миграция и отказ старому клиенту. Отдельно проверен запрет записи уже подключённого desktop-клиента старого протокола.

Самостоятельный psql-файл проверен отдельно от Go Migrate: подготовлена 009 с записью/историей, выполнен bundle и затем повторный запуск. В обоих случаях успех, журнал 16 записей, объект и история сохранены. Схема после проверки удалена.

## Сессии и события

Проверены:
- восстановление входа без пароля, хеш токена и срок 8 часов в PostgreSQL;
- истечение срока на сервере и запрет следующих запросов;
- выход, отзыв при смене пароля/блокировке, актуальная роль наблюдателя;
- изоляция по схеме, 0 часов, отрицательный/слишком большой срок;
- отказ системного хранилища с откатом токена и очисткой прикладного входа;
- повреждённые JSON/UUID локального токена: возврат к обычному входу;
- NOTIFY только после COMMIT, отсутствие при ROLLBACK;
- изоляция схем, объединение одинаковых сигналов транзакции;
- принудительное завершение слушающего backend PostgreSQL, переподключение и resync.

Браузерные сценарии дополнительно проверяют выбор часов, автоматический вход после перезагрузки, обновление выбранной карточки, игнорирование другой схемы, сохранность несохранённых полей редактора и возврат к авторизации при отзыве сессии. Playwright подменяет Wails bridge; настоящий PostgreSQL отдельно проверяется Go-тестами.

## Измерение SQL

Одна локальная база и транзакция, 100 серверов / 500 экземпляров / 100 000 синтетических БД, без политик и вложений, ANALYZE, jit=off, тёплый кеш, EXPLAIN (ANALYZE,BUFFERS). Старые запросы — из исходников 0.8.1 (6c2651a), затем на тех же данных применены новые миграции. Всё откатилось.

| Запрос | мс |
| --- | ---: |
| 0.8.1: только строки страницы одной ветки | 146,395 |
| 0.9.0: страница ветки с общими счётчиками, api_catalog_page | 13,839 |
| 0.8.1: общие счётчики с поиском точного SID | 184,404 |
| 0.9.0: страница и счётчики этого поиска, api_catalog_page | 27,758 |
| Локальный отбор поискового документа с pg_trgm | 0,894 |

Новая и старая команды возвращают разные объёмы служебных данных: это не одинаковые end-to-end сценарии. Сравнение показывает устранённую стоимость общего CTE; это разовые измерения SQL, не гарантия времени интерфейса/рабочей сети и не универсальный коэффициент ускорения.

Примеры новых команд:
~~~sql
EXPLAIN (ANALYZE,BUFFERS)
SELECT api_catalog_page('{}','instance','UUID_ЭКЗЕМПЛЯРА',0);

EXPLAIN (ANALYZE,BUFFERS)
SELECT api_catalog_page('{"query":"sid-100000"}','',NULL,0);
~~~

## Размер поставки

Windows EXE 0.8.1: 19 672 064 байт; 0.9.0: 19 680 256 байт (+8192 байта). Существенного уменьшения размера нет: добавлены сессии/слушатель и встроенные SQL-миграции, одновременно сокращена часть Go-реализации. ZIP 0.9.0 дополнительно содержит самостоятельный SQL-переход.

## Ограничения

Нативный запуск Windows/WebView2, Credential Manager с сохранённым токеном, два настоящих EXE, установщик/обновление и системные диалоги в этой среде не выполнены. Подготовлен Windows CI для обновления 0.8.1 → 0.9.0; его успешный нативный прогон здесь не подтверждён.

Разделение PostgreSQL-ролей и конфигурация pg_stat_statements не применялись на сервере. Удаление старой истории не выполняется. Более широкие блокировки импортов/переносов/восстановления сохранены; существенное уменьшение EXE не заявляется.
