# CatalogDB на Android-планшете

Android-клиент использует общий интерфейс React и ту же прикладную логику Go, что Windows/Linux. Он напрямую подключается к PostgreSQL: отдельный сервер приложения и PostgREST не требуются.

## Установка и подключение

1. Скачайте `CatalogDB-android-0.13.1.apk` из [GitHub Release](https://github.com/yomezza/dbcatalog/releases/tag/v0.13.1). Рядом опубликован SHA-256.
2. На планшете разрешите установку APK из выбранного браузера/файлового менеджера и откройте файл. Нужны **Android 8.0+**, актуальный системный WebView и архитектура ARMv7, ARM64 или x86_64. Google Play Services не требуются.
3. Укажите адрес PostgreSQL, порт, существующую базу, схему и PostgreSQL-учётную запись. `localhost` означает сам планшет; для рабочего сервера нужен доступный адрес, при необходимости — корпоративный VPN. Пустая схема означает `dbcatalog`.
4. Для рабочего подключения используйте TLS с проверкой сертификата. При собственном удостоверяющем центре нажмите **«Выбрать сертификат…»** и выберите X.509 PEM/DER до 2 МиБ. Копия сохраняется в закрытой папке приложения.
5. Подключение применяет те же автоматические миграции 001–016. Новая схема сначала предлагает создать администратора; существующая — войти пользователем приложения. Учётные записи приложения и PostgreSQL пока раздельные.

При обновлении существующего каталога сделайте резервную копию PostgreSQL. Удаление APK или очистка данных Android не удаляет центральный каталог, но удаляет локальные настройки, загрузки и сохранённый вход этого планшета.

## Управление

- В альбомной ориентации каталог и карточка расположены рядом; на более узком экране — друг под другом. Рабочая область первоначально свёрнута до иконок и раскрывается стрелкой.
- Меню объекта открывается кнопкой **⋮**. В нём доступны те же действия согласно роли пользователя. Системная кнопка «Назад» закрывает открытое окно/меню, затем предлагает закрыть приложение.
- Импорт Excel и прикрепление файлов используют системный выбор документов. «Сохранить как…» позволяет выбрать место для экспорта. Раздел «Загрузки» хранит локальную историю; **«Поделиться»** передаёт только выбранный файл другому приложению.
- RDP/SSH требуют установленного внешнего клиента с обработкой ссылок `rdp:`/`ssh:` и доступного порта 3389/22. APK не содержит терминал или RDP-клиент. Ошибки сертификата и удалённого входа обрабатывает внешний клиент.
- Обновления других пользователей поступают через общий LISTEN/NOTIFY. Android может остановить фоновое приложение; после возвращения выполняется повторное чтение. Постоянная фоновая служба и push-уведомления Android не реализованы.

Пароль подключения при выборе сохранения и токен входа шифруются AES-GCM с ключом Android Keystore. При недоступном хранилище секреты не записываются открытым текстом. Это не меняет полномочия самого PostgreSQL-подключения; действующие ограничения модели доступа описаны в [KNOWN_ISSUES.md](KNOWN_ISSUES.md).

## Сборка APK

Проверенная конфигурация: Go 1.27.3, Java compiler 21, Android platform 35, build-tools 35.0.0, NDK 27.2.12479018. Версия gomobile/gobind закреплена в `go.mod`.

```sh
go mod download
go install golang.org/x/mobile/cmd/gomobile@v0.0.0-20261011034528-197770444867
gomobile init
# init устанавливает gobind@latest; верните закреплённую версию:
go install golang.org/x/mobile/cmd/gobind@v0.0.0-20261011034528-197770444867
npm --prefix frontend ci
npm --prefix frontend run build
```

Добавьте Go binaries и Java binaries в PATH. Укажите `JAVA_HOME`, `ANDROID_HOME` и при необходимости `ANDROID_NDK_HOME`. SDK/NDK устанавливаются отдельно, скрипт приложения их не загружает.

Для подписи задайте пути к **своему существующему** закрытому ключу и файлам паролей вне Git:

```sh
export CATALOGDB_ANDROID_KEYSTORE=/private/catalogdb-release.p12
export CATALOGDB_ANDROID_KEY_ALIAS=catalogdb
export CATALOGDB_ANDROID_STORE_PASS_FILE=/private/store-password
export CATALOGDB_ANDROID_KEY_PASS_FILE=/private/key-password
bash packaging/build-android.sh
```

Результат — `build/bin/CatalogDB-android-VERSION.apk` и `.sha256`. Скрипт собирает три ABI, проверяет ELF LOAD alignment 16 КиБ, содержимое APK, ZIP alignment и APK-подпись. Gradle/AndroidX не используются. Обновляйте `versionName`/`versionCode` в `android/AndroidManifest.xml` вместе с версией приложения; `versionCode` обязан расти.

**Для обновления без удаления приложения необходимо сохранить тот же закрытый signing key.** Владелец должен хранить его резервную копию и пароли отдельно от исходников. Ключ выпуска 0.13.0 создан в закрытой папке текущей среды, в репозиторий и APK не включён; наличие ключа в другой облачной среде не гарантируется. SHA-256 публичного сертификата: `0dddc9db88b1edc1a9339d6d8dc9d2dec57f4775e7859e74d57b0e83f1095b94`.

Android job CI проверяет сборку с **одноразовым тестовым ключом**. Его APK нельзя использовать для обновления опубликованной установки; это отдельный артефакт `CI-test-only-not-release`.

## Нативная проверка

[Отчёт 0.13.1](validation-0.13.1.md) различает браузерные сценарии, интеграцию Go/PostgreSQL и настоящий Android. Для повторения нативного smoke есть отдельный instrumentation APK в `android/tests`, который не входит в приложение. Он подписывается тем же сертификатом и предназначен **только для одноразовой compose PostgreSQL** по `10.0.2.2:55432` из эмулятора:

```sh
adb install --no-incremental -r build/bin/CatalogDB-android-0.13.1.apk
bash packaging/android-native-smoke.sh android_smoke_unique create
adb shell am force-stop ru.dbcatalog.app
bash packaging/android-native-smoke.sh android_smoke_unique resume
```

Используйте новое имя `android_smoke_*` для первого прогона. Тест проверяет настоящий JS → Java → Go мост, создание схемы, вход, запись, событие каталога, XLSX, Keystore и повторный вход после перезапуска. Затем удалите тестовый APK (`adb uninstall ru.dbcatalog.smoke`) и созданную схему в одноразовой БД. Установка instrumentation с тем же сертификатом даёт ему доступ к приложению; его нельзя публиковать среди пользовательских файлов.

Внутренний контракт оболочки описан в [android/README.md](../android/README.md).

## Ошибка сертификатов на Huawei

На MatePad 12 X с HarmonyOS 4.3.0.146 установка 0.13.0 отклонена с текстом «В ходе анализа в установочном пакете не обнаружены сертификаты». Это сообщение установщика; оно не означает требование отдельного сертификата Huawei. Стандартная проверка v1/v2/v3 у исходного APK успешна.

0.13.1 использует тот же сертификат и подписи v1/v2, с именами `CERT.RSA` / `CERT.SF`. Это вариант для проверки совместимости, а не подтверждённое устранение причины на Huawei. Скачайте именно новый APK и попробуйте установку. Подтверждение от владельца планшета ещё не получено.

Если ошибка сохраняется, нужен подробный результат Package Manager: при подключённом по USB планшете с разрешённой отладкой выполните на компьютере `adb install -r CatalogDB-android-0.13.1.apk` и сохраните полный текст ошибки. Это установка/обновление с сохранением данных; удалять приложение или сертификаты не требуется.
