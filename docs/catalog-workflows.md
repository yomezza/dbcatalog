# Работа с каталогом: 0.7.0

## Выбор и массовое изменение

Флажок у БД выбирает её для массовых операций; открытие карточки — отдельное действие. «Выбрать все БД результата» заменяет выбор всеми БД текущего поиска/фильтра на всех страницах. «Снять выбор» очищает его. Смена фильтра сохраняет выбор, включая невидимые БД: счётчик явно показывает их количество. После обновления каталога выбор сбрасывается, чтобы не подменять сохранённые версии свежими.

Редактор и администратор могут менять ответственного, организацию, состояние и работу АБД. Отметьте нужные поля. Пустые ответственный/организация очищают поле, пустой список работы АБД очищает список; указанные значения списка полностью заменяют прежние. Состояние должно быть заполнено и входить в справочник.

«Предпросмотр изменений» показывает только изменяемые записи и поля с прежним/новым значениями. Смена любого поля отменяет предпросмотр. «Подтвердить изменения» выполняет одну транзакцию с историей по каждой БД и сводным событием аудита. Обновление/удаление хотя бы одной выбранной БД другим пользователем отменяет всю операцию; требуется обновить каталог и выбрать записи заново. Максимум — 10000 БД за одну массовую правку.

## Фильтры и наборы

«Фильтры баз данных» включает СУБД, состояние, промышленный/тестовый тип, ответственного (в том числе отсутствующего), политику РК: назначена, отсутствует, активна, отключена. У обычной БД СУБД берётся из экземпляра, у Oracle — из БД. Политика БД перекрывает политику экземпляра даже при отключении. Фильтры пересекаются между собой и с поиском «|».

При включённом фильтре дерево оставляет подходящие БД и их родителей; пустые серверы/экземпляры не попадают в результат. Без фильтров обычный поиск сохраняет прежнее поведение. Фильтры сами не раскрывают ветви — используйте стрелки или «Раскрыть все».

Укажите имя и сохраните набор: в PostgreSQL сохраняются все фильтры и строка поиска. Имя уникально без учёта регистра в пределах пользователя. Набор можно применить или удалить; это личные настройки текущего пользователя выбранной схемы, доступные всем ролям. Для нового набора с прежним именем сначала удалите старый.

## Качество данных

Раздел доступен всем вошедшим пользователям. Список обновляется при открытии и вручную. Категории: БД без ответственного, сервер без сетевого адреса, промышленная БД без эффективной политики РК/с отключённой политикой. Проверяются также совпадающие без учёта регистра имена серверов, общие адреса серверов и SID, различающиеся регистром внутри одного родителя.

Совпадения — повод для ручной проверки, а не автоматическое объединение. Один адрес может использоваться псевдонимами. Одинаковые SID на разных серверах/экземплярах допустимы. «Открыть карточку» переходит к объекту; серверный список выдаётся по 25 проблем на странице.

## Удалённые

Только администратор видит удалённые снимки и выполняет восстановление. Каскадное удаление и очистка каталога архивируют все затронутые объекты/политики в одной операции. Самостоятельно удалённая ранее БД не включается в последующее восстановление сервера: у неё другая операция удаления.

Выберите объект, оставьте «Восстановить всю удалённую ветвь» либо снимите флажок для одной записи. «Проверить восстановление» показывает состав и конфликты. Проверяются родители, уникальные имена/назначения, справочники и ограничения PostgreSQL. При восстановлении одной записи её родитель должен уже существовать. Для ветви родители восстанавливаются перед детьми, политики — после объектов. Если имя/назначение занято, сначала устраните конфликт в каталоге.

Проверка выполняет ту же операцию внутри откатываемой транзакции: объекты, история, версии, аудит и уведомления не сохраняются. При подтверждении состав и текущий каталог сверяются ещё раз. Вся ветвь восстанавливается атомарно под прежними UUID с новыми номерами версий. Промежуточные версии и история сохраняются. Личные ссылки избранного не восстанавливаются.

Архив удалений не заменяет резервную копию PostgreSQL. Миграция 008 поднимает доступные снимки прошлых удалений из истории; она не может восстановить отсутствовавшие в истории данные. Неполный старый снимок или отсутствующий родитель отображаются как конфликт. Устаревшие служебные экземпляры Oracle и их политики не предлагаются для восстановления.

## Экспорт

«Экспорт результата» выгружает только БД текущего поиска и фильтров со всех страниц. «Экспорт выбранного» учитывает весь текущий выбор, включая БД вне результата. В XLSX остаются исходные 21 колонка, одна строка на БД; данные родителей повторяются. Лист статистики выборочной выгрузки указывает число экспортированных БД. Полный экспорт остаётся в «Экспорт/Импорт».

Файл попадает в «Загрузки», затем открывается «Сохранить как…». Отмена диалога не удаляет запись загрузки. Если выбранная БД успела исчезнуть, экспорт требует обновить каталог, а не молча пропускает её.
