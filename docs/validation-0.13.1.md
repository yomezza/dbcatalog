# Проверка CatalogDB 0.13.1

25 октября 2026 года. Изменяется профиль подписи APK: v1/v2 с именем `CERT`, без v3/v4. Прикладная логика и PostgreSQL-схема 016 сохраняются. Сертификат тот же, что 0.13.0: SHA-256 `0dddc9db88b1edc1a9339d6d8dc9d2dec57f4775e7859e74d57b0e83f1095b94`; Android versionCode — 14.

## Причина выпуска и предел вывода

Владелец MatePad 12 X / HarmonyOS 4.3.0.146 показал отказ установщика: «В ходе анализа в установочном пакете не обнаружены сертификаты». У опубликованного 0.13.0 успешно проверены v1 отдельно, v2/v3, целостность ZIP и SHA-256. Отдельного требования сертификата Huawei из сообщения не следует.

Новый профиль — проверка совместимости со сканером/установщиком производителя. Причина отказа и успешная установка на этом Huawei **пока не подтверждены**. Физического планшета в среде проверки нет. Если отказ сохранится, нужен подробный вывод Package Manager через `adb install -r` либо сам фактически скачанный APK для проверки.

## Выполнено локально

| Проверка | Результат |
| --- | --- |
| Vitest, TypeScript/Vite | 14 тестов и production build пройдены |
| Go buildinfo/mobile с PostgreSQL 17 и race detector | Пройдены; мобильный bridge, авторизация, запись, событие, экспорт |
| Publisher | 6 тестов политики Latest/None пройдены |
| Android | Три ABI собраны; DEX/UI, ELF LOAD 16 КиБ, ZIP alignment проверены |
| Подписи APK | v2 успешно; v1 принудительно проверена отдельно с диапазоном проверки 21–23; CERT.RSA/SF присутствуют |
| Сертификат | SHA-256 совпадает с 0.13.0, новый ключ не создавался |
| Windows / Linux | Обе сборки 0.13.1 собраны; нативное Linux-окно проверено в D-Bus/Xvfb |

Принудительный диапазон 21–23 применяется только к проверке JAR-подписи; минимальная версия приложения остаётся Android 8 / API 26.

## Нативная проверка обновления в CI

В workflow добавлена проверка обновления: предыдущий APK 0.13.0 подписывается одноразовым ключом CI, в нём создаются данные/сохранённый вход; затем поверх устанавливается новый APK v1/v2 с тем же тестовым сертификатом. Вторая фаза проверяет Keystore, подключение, восстановление сессии и сохранность записи. Закрытый release key в CI не передаётся; изменённый тестовый 0.13.0 не публикуется.

[CI 40211915468](https://github.com/yomezza/dbcatalog/actions/runs/40211915468), исходники `152f906`: все четыре задачи (backend, Windows, Linux, Android) завершились успешно. На Android 15 / Nexus 7 с KVM успешно выполнены создание данных в 0.13.0, обновление на 0.13.1 и восстановление сохранённого входа/записи. Логи — в артефакте `CatalogDB-android-native-report`. Это проверка стандартного Android, а не прошивки Huawei. Проверки общей логики и 50 браузерных сценариев предыдущего выпуска описаны в [0.13.0](validation-0.13.0.md); UI и SQL в текущем изменении не правились.
