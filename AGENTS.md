# Правила выпуска CatalogDB

При выпуске каждой новой версии приложения обязательно публикуйте соответствующий GitHub Release в yomezza/test. Это постоянное требование пользователя.

- Собирайте Windows x64 и Linux x64 из одной версии исходников; выполняйте подходящие проверки.
- Сохраняйте архивы и SHA-256 в downloads. Не заменяйте файлы уже опубликованных версий другим содержимым.
- Добавляйте версию в packaging/releases/manifest.json с описанием изменений, полным SHA коммита с архивами и всеми вложениями.
- Создавайте тег vVERSION на соответствующий коммит. При существующем теге не передавайте target_commitish в запрос создания Release.
- Запускайте python3 packaging/publish-releases.py для проверки. После push манифеста workflow Publish CatalogDB releases публикует выпуск через CATALOGDB_RELEASE_TOKEN.
- До сообщения об окончании выпуска проверяйте успешность публикации, публичную страницу Release и доступность всех файлов. Не ограничивайтесь файлами в downloads или артефактами Actions.
- Не считайте задачу выпуска завершённой, если публикация заблокирована; сообщите конкретную причину. Никогда не выводите токены в чат или исходники.
