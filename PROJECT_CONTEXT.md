## Назначение

**CatalogDB («Каталог БД»)** — настольное приложение для общего учёта инфраструктуры:

```text
сервер → экземпляр СУБД → базы данных
сервер → группа «Oracle Database» → Oracle SID
```

Оно хранит сведения о размещении, СУБД, эксплуатации, ответственных, сопровождении, политиках РК, документах и изменениях. Карточка представляет описание инфраструктуры. Создание или удаление карточки не создаёт и не удаляет реальную обслуживаемую БД.

Интерфейс русский. Пользователь предпочитает краткое общение и выполнение явно порученных изменений без повторных подтверждений обычных действий. Он также отдельно просит режим обсуждения для некоторых архитектурных идей — его нужно соблюдать.

## Архитектура и карта исходников

В первоначальном задании упоминался Python. По решению пользователя проект реализован на **Go**. Текущий стек: **Go + React/TypeScript + PostgreSQL 17**, Wails v2 для Windows/Linux и Java WebView + gomobile для Android. Все платформы используют `internal/application`; отдельного сетевого backend нет.

Приложение напрямую соединяется с центральной PostgreSQL. Отдельного HTTP-сервиса Go и PostgREST нет. Термин **SQL API** в документах означает функции внутри схемы PostgreSQL.

## Реализованные возможности и принятые правила

### Подключение и авторизация

- Существующую PostgreSQL-базу создаёт администратор. Приложение создаёт и обновляет выбранную схему внутри неё; default — `dbcatalog`.
- Смена схемы открывает изолированный каталог со своими пользователями и записями. Переноса данных при этом нет.
- Миграции встроены в Go, применяются с блокировкой и проверкой SHA-256. Применённые миграции не переписываются.
- Учётная запись PostgreSQL и пользователь приложения пока **раздельные**. Первый пользователь новой схемы создаётся администратором, последующие регистрации ожидают активации.
- Прикладные роли: `admin`, `editor`, `viewer`. Наблюдатель читает и экспортирует; редактор меняет данные; административные операции, удаления и возврат версий доступны администратору.
- Пароли приложения хешируются Argon2id. Для сохранения входа на 1–168 часов используется случайный токен в системном хранилище и его хеш в PostgreSQL; 0 — без сохранения. Пароль PostgreSQL сохраняется отдельно при выборе пользователя.
- Ограничения прямых прав БД и обычных открытых сеансов описаны в KNOWN_ISSUES.md. Не выдавайте прикладные роли за защиту от владельца широких SQL-реквизитов.

### Структура, поиск и большие каталоги

- Обычная БД принадлежит экземпляру, Oracle SID — непосредственно серверу. Ветка «Oracle Database» служит группировкой и не создаёт обязательный экземпляр.
- SID уникален в рамках своего родителя; одинаковые SID на разных серверах/экземплярах допустимы.
- `TEST1 | TEST2` — **И**, поиск буквальных подстрок без учёта регистра в одной цепочке. Совпадения разных соседних БД не складываются.
- Поиск учитывает поля, метаданные вложений и текст созданных инструкций; содержимое загруженных PDF/двоичных файлов не индексируется.
- Поиск, фильтры, счётчики, выбор всего результата и экспорт работают глобально в PostgreSQL, независимо от раскрытия ветвей и загруженных страниц.
- Корень выдаёт по 10 серверов, ветви — по 100 объектов. Есть загрузка по раскрытию, виртуализация, глобальный выбор родителей, переход к скрытому объекту.
- Выбор всего результата и массовая правка — до 10 000 БД; экспорт результата — до 100 000. Превышение требует сузить условия, без тихого усечения.
- Ветки изначально свёрнуты; раскрываются стрелкой или двойным ЛКМ. Есть ПКМ, избранное, фильтры и личные наборы фильтров.
- В 0.12.0 боковая рабочая область сворачивается до 72 px. Выбор сохраняется локально в WebView; подсказки, активный раздел, уведомления и выход остаются доступны. Есть работа с клавиатуры и без localStorage.

### Импорт, экспорт и политики РК

- XLS/XLSX: 21 колонка каталога либо 28 с полями РК. Одна строка — одна БД, данные родителей повторяются. Порядок заголовков определён в `internal/spreadsheet/workbook.go`.
- Сервер сопоставляется без учёта регистра и крайних пробелов; экземпляр и SID — точно, внутри родителей. Повторные строки одного сервера должны сообщать одинаковые общие параметры.
- Для Oracle колонка экземпляра игнорируется, включая пустое значение и `default`. Для других СУБД экземпляр обязателен.
- Предпросмотр связан с пользователем, действует 10 минут. Исправление или исключение строк пересчитывает план и отменяет прежние подтверждения. До подтверждения объекты каталога не записываются.
- При подтверждении повторно проверяются права, состав и версии. Конфликт откатывает транзакцию. Пустые ячейки при обновлении сохраняют прежние значения; очистка поля требует явного редактирования.
- Строки можно исключать и возвращать; исходный файл не меняется. Исправленная копия содержит только 21 колонку оставшихся строк, без переноса политик РК.
- Колонки паролей архива 27–28 не переносятся в модель, PostgreSQL, историю или журналы.
- Для политик РК отдельно подтверждаются цель, расписание, единицы срока и замена существующих настроек. Собственная политика БД перекрывает политику экземпляра, даже если отключена. Oracle — непосредственное назначение БД.
- Политики описывают настройки: приложение не выполняет копирование и не получает отчёты о фактических копиях.
- «Работа АБД» — множественный выбор. Месторасположение, организация, руководитель и ответственный допускают подсказки и собственные значения. Точные справочники — в схеме и исходниках.

### PDF-паспорта

- «Печать в PDF» в карточке и меню объекта; на Android доступна через ⋮. Физической печати пока нет.
- `internal/reports` формирует A4 с встроенными Noto Sans (OFL), цветными статусами, разделами и нумерацией. `internal/application/passport.go` читает актуальные данные и родителей в одном авторизованном снимке PostgreSQL.
- Собственная политика РК, включая отключённую, перекрывает унаследованную. Oracle не требует экземпляра. В паспорт входят только явно выбранные поля, не секреты подключения.
- PDF остаётся в локальных «Загрузках» при отмене «Сохранить как…»; наблюдатель может экспортировать, формирование фиксируется в аудите. Не обещать фактическую успешность копий, PDF/A или электронную подпись.
- [Руководство](docs/object-passports.md), [синтетический пример](docs/examples/CatalogDB-passport-demo.pdf). Схема остаётся 016.

### История, удаление, файлы

- Удаление родителя каскадно обрабатывает дочерние объекты и политики. Рабочие записи физически удаляются после архивирования их состояний, а не просто помечаются в той же строке.
- «Удалённые» позволяют администратору восстановить объект или ветвь той же операции удаления с проверкой родителей, имён и назначений. Сохраняется UUID, создаются новые версии; избранное отмечается заново.
- Возврат к версии существующей записи также создаёт новую версию, не стирает промежуточные и не восстанавливает удалённых детей автоматически.
- История, версии, перемещения и подробности аудита открываются в отдельных окнах. История и архив удалений не заменяют резервную копию PostgreSQL.
- Общие вложения до 20 МиБ хранятся в PostgreSQL; есть редактируемые инструкции с формированием DOCX. Перенос сохраняет связь по UUID.
- При удалении объекта его вложения остаются и вновь доступны после восстановления. Удаление самого вложения физическое; автоматической очистки осиротевших файлов нет.
- «Загрузки» — локальные файлы текущего рабочего места, подключения и пользователя. Отмена «Сохранить как…» не удаляет созданный экспорт. SQL/PS1 автоматически не запускаются.
- RDP/SSH открываются внешними клиентами по адресу родительского сервера, стандартные порты 3389/22. Проверка TCP-порта не подтверждает удалённую авторизацию.

### Обновления и диагностика

- Динамичность **уже реализована**: SQL-триггеры → NOTIFY после COMMIT → отдельное LISTEN-соединение в процессе Go → событие Wails либо Android bridge → повторное чтение данных UI.
- Есть объединение событий, переподключение, resync при возвращении окна и контрольный опрос раз в минуту. NOTIFY — сигнал перечитать состояние, не надёжная очередь.
- Открытые формы не перезаписываются; сохранение проверяет версии. Смена схемы/сессии не должна применять устаревшие ответы.
- Диагностика доступна без авторизации: версии, PostgreSQL/TLS, миграции, слушатель, последняя операция системного хранилища. JSON строится по разрешённому списку без секретов, адресов и данных карточек.

## Обсуждалось, но не реализовано

### Персональные PostgreSQL-логины

Пользователь предложил убрать собственную проверку паролей приложения и использовать личные PostgreSQL-учётные записи. Он явно попросил **пока обдумывать, не реализовывать**.

Обсуждённое направление: персональное соединение PostgreSQL, определение автора по `session_user`, защищённая привязка PG-роли к UUID профиля каталога и прикладным полномочиям, отдельная учётка миграций. UUID профилей и внешние ссылки истории/избранного/уведомлений нужно сохранить. OID роли PostgreSQL не является переносимым UUID между кластерами. Права администратора каталога не должны автоматически давать superuser/CREATEROLE.

Это направление ещё требует проектирования миграции пользователей, прав, управления паролями и сохранения входа. Простая замена экрана логина не устраняет обходы SQL-прав.

### PostgREST и отчёты резервного копирования

Обсуждалось получение отчётов PowerShell по API, хранение результатов РК и уведомления о сбоях/пропущенных копиях. Пользователь интересовался именно **PostgREST**, не хотел отдельного Go-сервиса, затем отложил идею. Ни PostgREST, ни отдельный приёмник отчётов не внедрены.

### Размер исполняемого файла

Оптимизация размера EXE обсуждалась, затем пользователь попросил оставить эту тему. Не удаляйте функции и не внедряйте упаковщики ради размера без новой задачи.

## Android 0.13.0

- Основной сценарий — **планшет**, ответ пользователя на уточнение. Минимум Android 8 / API 26, target 35; APK включает ARMv7, ARM64, x86_64. Google Play Services не нужны.
- Java Activity загружает только встроенный React UI с фиксированного HTTPS origin. `mobile.Client` вызывает существующий Go service по явному списку методов; авторизация и транзакции остаются общими.
- Секреты — Keystore AES-GCM; SAF выбирает/сохраняет документы и корневой сертификат. Закрытый ContentProvider передаёт выбранный экспорт внешнему приложению. «Поделиться» заменяет открытие папки загрузок.
- На узком экране каталог/карточка идут последовательно; кнопка ⋮ заменяет необходимость ПКМ, боковая панель первоначально компактна. Windows/Linux стили изолированы от Android CSS.
- Постоянная фоновая служба и системные push-уведомления Android не внедрены. Возврат приложения вызывает resync. RDP/SSH требуют внешнего клиента.
- Ключ подписи находится вне Git в закрытой папке текущей среды. Для будущих обновлений обязателен тот же signing key и растущий versionCode; владелец должен обеспечить отдельную резервную копию ключа. CI использует одноразовый тестовый сертификат, его APK не заменяет release APK.
- Нативный smoke — отдельный instrumentation APK (`android/tests`), не часть распространяемого приложения. Обе фазы (включая Keystore после остановки процесса) прошли в GitHub Actions на KVM, Android 15 / Nexus 7: workflow `40208820170`. Только синтетическая compose БД и схема `android_smoke_*`.

## Установка на Huawei: текущая диагностика

MatePad 12 X / HarmonyOS 4.3.0.146 отклонил APK 0.13.0: «В ходе анализа в установочном пакете не обнаружены сертификаты». Это не HarmonyOS NEXT. Исходный APK проходит `apksigner` v1/v2/v3; реальная причина отказа Huawei не подтверждена. Пользователь сообщил об автоматическом времени, отдельного подтверждения даты нет.

0.13.1 — подписи v1/v2 с JAR-именем `CERT`, без смены сертификата, versionCode 14. Обновление 0.13.0 → 0.13.1 с сохранением входа/данных проверено на Android 15/KVM в CI `40211915468`; все четыре CI-задачи успешны. Не утверждайте, что Huawei уже исправлен, пока пользователь не подтвердит установку. Если отказ сохраняется, нужен полный код/текст ошибки `adb install -r` либо проверка фактически скачанного APK. Не предлагайте устанавливать сторонние сертификаты или менять signing key.

## Политика выпуска

Пользователь требует Release для каждой новой версии. Для 0.13.0 и далее предпочтительна метка **Latest**, иначе **None**, не Pre-release. Publisher уже поддерживает строковое `make_latest: "true"/"false"` и `prerelease: false`; старые записи без `make_latest` сохраняют фактические labels GitHub.
